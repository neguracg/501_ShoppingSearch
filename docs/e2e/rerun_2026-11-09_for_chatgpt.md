# 楽天MCP E2E 再試験の依頼（2026-11-09）

前回の E2E（既存80件 v1.1・追加60件 v3、2026-11-06 00:05〜00:50 実施）の後に、MCP 側を3回修正して本番へ反映した（2026-11-06 09:32 完了）。同じ ChatGPT 通常チャット → 楽天MCP → 楽天API の経路で、**修正した不具合が直ったか**と、**新しく入れた「要確認」の印が回答に正しく反映されるか**を再試験してほしい。

## 1. 変わったこと（MCP 側）

| 版 | 内容 | 期待される見え方 |
|---|---|---|
| WP8 | 題名の中に食い違う数字がある時は数量を確定しない（`confidence=low`＝単価不明） | 紙幅109mm・`30m12R`・`【48本】…48本 2ケース`・`選べる 1本/3本/5本`・`最大700g…1kgより少ない` が単価不明になる |
| WP8 | 楽天APIが拒否する「漢字以外の1文字だけの語」を送る前に止め、理由を返す（`keyword_term_too_short`） | `EcoFlow DELTA 2`・`ヌプシジャケット L` が HTTP 400 ではなく「『DELTA2』のように前の語とつなげて」という入力誤りで返る |
| WP9 | 型番の中の量（`ICBK80L` の 80L）と同じ量が単独で書かれている時、`+` でつないだ構成品の個数（`本体+バッテリ2個+充電器`）は確定しない | インク80L・工具セットのバッテリー2個が単価不明になる |
| WP10 | 同じ比較の中で単位価格が中央値の 1/10 未満の候補に `unit_price_outlier: true`（要確認）を付け、`cheapest_unit_price`・`cheapest_for_quantity` から外す。候補一覧には残し、caveats に件数を出す。比較の候補が4件未満の時は判定しない | 型番を量と読んだ等の桁違いに安い候補が単位価格の最安に出ない。ChatGPT は要確認の候補を最安として勧めず、商品ページでの確認を促すのが正しい |

**変わっていないこと（今回の再試験では FAIL のままでよい・別途判断待ち）**: 商品の種類・仕様の取り違え（ソーラーパネル検索のLEGO部品、本体検索の交換フィルター、純正指定の互換品、1000 New 指定の 1500 New、単3/単4 混在、炭酸/非炭酸、本体/詰め替え、24本指定に48本）と、複数商品の組合せ購入（20本+40本）。MCP は商品の意味を判定しない設計で、ChatGPT 側が除外できたかだけを見る。

**既知の限界（FAIL が出ても想定内。記録だけ）**: 2〜5倍程度の数量の読み違い（`1個・3個` のような択一、`54枚×4パック(216枚)` を864枚と読む約4倍の誤り）は要確認の網にも掛からない。数量は商品名からの読み取りで誤り得る旨は caveats に常に出る。
