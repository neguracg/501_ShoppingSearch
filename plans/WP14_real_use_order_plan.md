## 作業単位（この順。各単位ごとに commit・WORKLOG 1行）

### W1 選択肢で価格が変わる印（adapter・models・pricing・service）

- adapter: `itemPriceMin3`/`itemPriceMax3`（無ければ 1→2 の順で）を `Offer.price_min`/`price_max` に。`price_varies = (min と max が両方あり min≠max)`。`asurakuFlag`/`asurakuClosingTime` も Offer へ（null 可）。
- 比較: `price_varies` の候補は **数量を使う最安（cheapest_unit_price・cheapest_for_quantity・W2 の注文の最安）に選ばない**。一覧・グループには残し、単位価格は表示価格で出す（`unit_price` は今のまま。範囲 `price_min〜price_max` も dict に出す）。cheapest_price は今のまま（事実として最小の選択肢の価格）。
- caveats に件数行「選択肢によって価格が変わる候補: N件（表示価格が商品名の数量の選択肢の価格とは限らないため、単位価格・注文の最安から外した）」。
- 「逆転し得る候補」（W2 の `to_check`）に入れる: 表示価格で計算すると確認済みの最安より安い時、「商品名の数量（60枚）の選択肢が X円以下ならこちらが安い」の X を出す。

### W2 希望量を注文する組み合わせ（pricing。SPEC §8 Q10 の変更＝B 分類）

- 入力: `desired_quantity`（下限。basis の単位）に加え `desired_quantity_max`（上限・任意）。MCP・CLI・service・inputs の検査を同じ関数で。
- 各候補（単位の量が読めた候補）について「同じ商品を n 個注文」: n = ceil(下限 / 1個の量)、注文量 = n×量、上限があれば 注文量 ≤ 上限 の時だけ範囲内、注文額 = n×価格、注文の単価 = 注文額 / 注文量。送料は `shipping_status` をそのまま（込みなら n 個でも込み）。異なる商品の混ぜ合わせはしない。
- 結果 `order_plans`（範囲内の候補を注文額の安い順。各 n・注文量・注文額・注文の単価・送料の状態・確認済みか・確認済みでない理由）と、
  - `cheapest_order`: **確認済み**（数量が商品名から high・価格が選択肢で変わらない・外れ値でない・送料込み）の中で注文額が最小。
  - `to_check`（逆転し得る候補）: 注文額が cheapest_order より安いが確認済みでない候補と、その条件。送料別・送料不明 →「注文全体の送料が X円未満ならこちらが安い（X = cheapest_order の注文額 − この注文額）」。選択肢で価格が変わる → W1 の条件。説明欄から補完した数量 → 「説明欄『■数量:18本入り』の数量が正しければ」。確認済みが1件も無い時は、条件付きの候補を安い順に出し、何が足りないかを書く。
  - **送料無料ライン（3,980円）を仮定しない**。送料別の候補の注文額がそれを超えても送料込みにしない（楽天公式 FAQ: ライン超えでも送料がかかる商品がある。https://ichiba.faq.rakuten.net/detail/000013788 ）。caveats に1行。
- 既存の `cheapest_for_quantity` は互換のため残し、意味を「cheapest_order と同じ候補」に揃える（1個買いだけの判定はやめる）。Web 画面の表示が壊れないこと。

### W3 数え語ごとのグループ（pricing）

- basis「個」の比較では **count_unit ごとにグループを分ける**（本・袋・枚・ロール・個…）。単位価格の最安・注文の最安はグループをまたいで比べない。どのグループで比べたかを結果に出す（`groups[].count_unit`）。最安を1つに決められない時は、グループごとの最安を出し caveats に「数え方の違う候補（本と袋）は比べていない」。
- basis に数え語の正規名（本・袋・枚・ロール 等、COUNTERS の正規名）を指定できるようにし、その count_unit の候補だけで比べる（`basis="本"`）。inputs.check_basis に足す。

### W4 説明欄の見出し付きの数量で補完（新モジュール。quantity.py の題名の読み取りは変えない）

- 新しい所有モジュール（例 `caption_quantity.py`。`@owns 説明欄の見出し付き記述からの数量の補完`）。quantity.py・ブラインド試験・題名コーパスの出力は**バイト単位で不変**。
- 対象は見出しの直後の記述だけ: 見出しは `入数`・`入り数`・`内容量`・`数量`・`容量`（＋区切り `:`・`：`・空白・なし）。値は次の `■`・`●`・`◆`・`【`・別の見出し・句点、または 40 字まで。値を `parse_quantity` で読み、high の物だけ。見出しが複数あれば全部が同じ総数の時だけ採る（P0 と同じ一致原則）。
- 採らない所（位置で除外。語のリストではなく区切りで）: `関連キーワード`・`本商品の説明ではありません` 以降、`はこちら` を含む文、見出しの無い文中の数（`本品を1～2 本`・`まめカイロ7枚`・`15点以上`）。
- 使う時: **題名の confidence が none の時だけ**補完する（low は題名に食い違う数があるので補完しない。low で説明欄が読めた件数は測定して報告だけ）。題名が high で説明欄と食い違う時は confidence を変えず `caption_conflict` の印と根拠だけ出す。
- 補完した数量は `quantity.source="caption"`・`quantity.caption_evidence`（見出しから値までの原文）を持つ。単位価格は出してグループに並べるが、**確認済みではない**（W1・W2 の最安には選ばず、安ければ `to_check` に条件付きで出す）。題名由来は `source="title"`。
- 実測（必須）: 実 API で 3 件の検索語＋WP10 の 30 語程度（pages=1）を取り、題名 none の候補のうち補完できた件数・人が見て誤り件数・題名 high との食い違い件数を表で報告。WP11-2（全文の照合は誤り 1 件拾うごとに単価不明 8 件増）と違い見出し付きの値だけで、題名 none の補完に限ることを比べて書く。誤りが多い（目安: 補完の 10% 超）なら W4 は印だけ出して単位価格を出さない形に縮め、報告で止める。

### W5 題名の読み取り（quantity.py。P0 で low に倒す・WP13 を含む）

- (a) **途中切れの末尾**: × の鎖（`12ロール×4パック`）と同じ数え語・同じ数の単独の個数（`（12ロール` で終わる）は、その鎖の内側の言い直しとして食い違いにしない（今の「12ロール入り」の扱いを `入り` の無い同じ形へ。× の鎖に限る。空白だけの鎖 `48本 2ケース` の前置きは WP8 のまま low）。yumenokoya の実題名が 48ロール high になること。
- (b) **`N<数え語> M個パック`／`M個セット`**（外側が「数字＋個＋容器語」の複合で、内側に `入` も `×` も無い）は、N が合計か1つあたりか決まらないので low。`36本 2個パック` → low。`18本入り×2個セット`・`単3 4本入 3パック`・`コピー用紙 500枚 5冊` は不変。
- (c) **WP13**: plans/WP13_declared_total_chain.md をそのまま実施（先頭の個数が後ろの「内容量×個数の鎖」に掛けられる 2304 本の誤読）。
- 各項目の前後でコーパス 452 件の出力の変化を一覧で報告（変わる物は正誤を付ける）。ブラインドは件数だけ。

### W6 呼び出し側の AI への説明（mcp_server の INSTRUCTIONS・ツール説明。文は1か所）

- 希望量が範囲（「50〜100枚くらい」）の時は `desired_quantity`=下限・`desired_quantity_max`=上限で呼ぶ。検索語に枚数を必須にしない（他の枚数・複数注文を落とす）。枚数を外した語で、`sort=standard` と `sort=+itemPrice` の2回（または pages を増やす）で拾ってから比べる。
- 回答は `cheapest_order`（確認済みの最安）・`to_check`（逆転し得る候補と条件）・確定に足りない条件の3つで。`price_varies` の候補を「○枚○円」と断定しない。送料無料ラインを仮定しない。発送目安・送料額は API に無いので商品ページで確認と書く（あす楽の印がある時だけそれを書く）。
- 「18本入りを30袋」のような依頼は、数え方を揃えて（basis=本・desired=540、または basis=袋）比べ、数え方の違う候補を同じ単価順に並べない。
- 紙幅などの仕様は道具が判定しない（SPEC §7・§8 のまま）。`caption` の見出し付きの仕様（`■ロールサイズ：幅114mm×長さ100m`）を AI が照合し、違う可能性がある候補は同一品と分けて示す、と書く。
